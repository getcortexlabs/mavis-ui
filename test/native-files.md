# Native file selection and upload status

Build packages first, install dependencies in `examples/catalog`, then build with `ns build ios --emulator --no-hmr --env.inputCheck=files` or `ns build android --no-hmr --env.inputCheck=files`. Install on the isolated task device. The shared fixture is `/checks/files`; it accepts `.txt`, `.pdf` and images, at most three files and 2048 bytes each. Its upload callback only simulates progress and failures; no file is transmitted.

1. Make `test/fixtures/files/notes.txt` available in the device's document provider. Android can use the task emulator's Download folder. On a fresh iOS simulator, expose a test app Documents directory through temporary **built-app-only** `UIFileSharingEnabled` and `LSSupportsOpeningDocumentsInPlace` keys and copy the fixture there. Rebuild normally afterwards to remove these test-only settings. Mavis does not require these settings in a consuming app: they expose a source fixture to Files, while the picker can select from existing document providers without them.
2. Activate Choose files. Verify iOS Files / Android DocumentsUI actually opens. On Android, wait until the owner Activity has stopped: the picker must remain open. NativeScript calls `unloaded` during this intentional handoff, so it must not be confused with leaving the Vue owner.
3. Choose `notes.txt` and confirm the system selection. Verify the name, 62-byte size and `text/plain` metadata. iOS may display a Quick Look preview; Android text documents may have no provider thumbnail. Missing/failed previews must keep the file and actions.
4. Open the system picker again and cancel. Confirm that accepted items remain unchanged and `picking` returns to false. Repeated selection must work. In multiple mode, a separate accepted selection receives a new ID, even with the same name.
5. Turn on Fail next upload using the actual switch, then Upload. Check the failure message and Retry. Retry, then Cancel while active; it must become cancelled and keep the file. Retry again and allow success. The fixture takes about two seconds, so coordinate taps without waiting for a slow accessibility-tree dump between Retry and Cancel.
6. Remove the item. Check the empty state and confirm the original provider file still exists. Reopen/cancel the picker. Disable the control and verify its selection/actions are unavailable.
7. Navigate away or unmount the owner while work is active; no late progress/completion may restore a removed item. The controller unit tests cover ignored late promises and resource release. The native `getNativeFile` accessor exposes the session URI/NSURL and streams; all opened streams must be closed by the host or on resource release.

Native errors are recoverable selection errors, not application crashes. Android `EXTRA_MIME_TYPES` must receive an actual Java `String[]`: passing a JavaScript array can select the Bundle overload in the bridge. iOS uses `asCopy=true`; release removes the imported temporary copy, never the source document. Do not persist native handles or URI/path strings as shared state.

Record platform version, build flags, fixture setup, screenshots and accepted state snapshots. Distinguish emulator/simulator interaction from physical-device, cloud-provider, reader or hardware-keyboard coverage. Restore any font/appearance settings and remove only the task-owned devices after the broader native batch has finished. Keep evidence under ignored `artifacts/lume-native`.

## Recorded validation for this delivery

Both full builds completed with the files fixture. iPhone 17 / iOS 26.2 Simulator exercised the real Files picker, selection of the 62-byte text fixture, name/type/size, a Quick Look preview, known simulated progress, success, removal, reopening and system cancellation. Pixel 7 / Android 15 API 35 Emulator exercised the real DocumentsUI selector, the same metadata, failure, retry, cancellation of an active attempt, another retry through success, removal, reopening and system Back cancellation. Both source fixtures remained intact. Android intentionally used API 35 after the API 36 image's minimum userdata allocation exceeded available host storage; this is not API 36 runtime evidence.

The native sessions did not exercise unknown-total progress, large system fonts, image selections, third-party/cloud document providers, process restart with a selected resource, or a real transport reading stream bytes. Web browser tests cover image object URLs, repeated selection, validation, keyboard/focus, unknown progress, late completion and 320px/doubled-text layout. Unit tests cover native accessor lifetime/stream closing, optional preview failure, SSR metadata and stale operation completion. There was no physical-device, VoiceOver/TalkBack speech, external keyboard, third-party IME or background-transfer audit.

The attempted iOS failure-switch sequence did not produce a failure and is not counted as retry/cancel coverage; those transitions were observed on Android and the browsers. Two product issues found by actual Android execution were corrected and rechecked: the MIME String-array bridge overload and cancellation during the system picker's owner-Activity stop.
